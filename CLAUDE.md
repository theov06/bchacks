# BCHacks website — rules for every session

Full spec: docs/DESIGN_SPEC.md. Section 0 is the current concept (v3), with the v3.1 changes in 0.8 (they win); refer to requirement IDs (G1, D2, T5, A3…) from it. Visual spec: docs/bchacks-design-reference-v3/ (mockup index.html, assets/, screenshots/). The mockup is a visual spec only: never ship it or copy the file into the site.

- Concept v3 "Journey down the valley": scrolling the homepage travels down through the Okanagan, one illustrated scene per section: hero sunset → About/Explore northern lights + 3D island → Gallery (past photos) night sky → Schedule Myra Canyon → Sponsors wineries → Get involved on the lake → FAQ underwater → footer lakebed. Each scene's bottom colour matches the next section's top colour.
- UI is the sticker style: cream #FFF8EC cards, 3px #0E1446 ink border, rounded 14–24px corners, solid offset shadows (no blur). Buttons the same. One highlighted phrase per heading in the section's accent. Titles (hero h1, section h2s, footer headline, page h1s) are Geist Pixel 400 with a metric-matched fallback and no negative tracking; everything else Inter / JetBrains Mono.
- Scenes are components that inline their SVG (src/assets/scenes/, optimised by scripts/scenes/build.mjs; every id prefixed per scene). Decoration only: aria-hidden, pointer-events none, never hold information. Keep each scene's colours, layout and proportions; text never sits on the busy part of a scene. Phones get their own crop per scene that keeps the key feature in view.
- The FAQ's deep shadow is faint, faceless and abstract, and is never named after any figure: not in copy, alt text, ids, class names, comments or file names. In code it is "deep-shadow". Never use the Ogopogo (Syilx sacred figure). The mascot is a California quail.
- The 3D island lives in About/Explore (not the hero): lazy-loaded near that section, island.png is the fallback (no WebGL, low power, reduced motion), hotspot chips are real links. Decoration only: never blocks clicks, never traps scrolling.
- Tokens live in src/styles/tokens.css (scene base colours included). Don't add colours outside the v3 mockup's palette.
- Text contrast WCAG 2.2 AA on every scene: light text on dark scenes, dark ink on the lake. Check text against the rendered pixels behind it, not just the base colour.
- All editable content lives in content/*.ts. Components never hard-code event facts. Every [bracketed] placeholder from the mockup is a content value marked CONFIRM; never invent tracks, times, sponsors, team size or eligibility.
- Site state (offseason / open / closed / live) is one value in content/site.ts.
- Accessibility target WCAG 2.2 AA; touch targets ≥44px; visible focus ring on every link, chip, accordion and button. prefers-reduced-motion = every scene still and island.png for the island.
- Motion (step 3): CSS keyframes on transform/opacity only, calm and slow, staggered; scenes pause off-screen and in hidden tabs.
- Pre-rendered HTML; content reads without JavaScript. First-paint JS < 100KB gz. 3D (R3F + drei + three) loads lazily; bundle + assets ≤ 3MB; quality tiers high / medium / static; pixel ratio ≤ 2; pause off-screen and in hidden tabs. 3D assets: built in code or CC0 only, listed in docs/CREDITS.md.
- Visual checks: Playwright screenshots at 390, 1440 and 1920, side by side with the v3 screenshots (scripts/visual/compare.mjs); list and fix every difference before showing. Hero checks: scripts/visual/hero-fit.mjs (1280×720, 1440×900, 1920×990, 2560×1300, 390×844). 3D: `npm run shots -- <path> <outDir>` (SwiftShader WebGL). After every visual change, take screenshots and look at them before saying it's done.
- Stack: Astro + TypeScript, static output. Components are typed `.tsx` function components (src/components/ui|layout|sections) rendered by @astrojs/react at build time. Never add `client:*` directives; interactivity goes in src/scripts/*.ts, loaded from a `<script>` in the page or layout (the 3D world mounts itself with createRoot from there). Styles are CSS modules next to each component; state hooks use data-attributes, not classes. Fonts via @fontsource (Inter 400/500/700/800, JetBrains Mono 500, Geist Pixel 400).
- Voice: energetic and bold, short sentences, never hype past the facts. Only confirmed claims (see PRODUCT.md).
- v3.1 (spec 0.8): content/site.ts applyMode "soon" | "open": "soon" sends every Apply button to /apply, "open" to applyUrl (and /apply redirects). There is no /sponsor page (it redirects to /#sponsors): every sponsor CTA opens the one sponsor pop-up form (data-sponsor-open) and is a plain link without JS. Hosting is Netlify. Sponsor leads go to the team's Google Sheet through a Google Apps Script web app (scripts/sponsor-sheet/Code.gs, URL in site.sponsorForm.sheetUrl); the team sends the deck by hand, so never promise it "in a few minutes". The sign-up form uses Netlify Forms.
- 3D (spec 0.8.6): one shared WebGL renderer for the whole page, never one context per section.
